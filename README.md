# JapRead

通过阅读日语新闻、文章和小说，把理解原文、积累知识与测验复习连接起来。

**当前已有 0.1 真实阅读小版本，尚未发布安装包。** 已实现青空文库选书／本地文本导入、章节阅读、手工／JSON 标注、知识回链、学习选择与 SQLite 持久化。下文「规划能力」仍包含未实现的长期目标；实际完成情况见 [TODO](TODO.md)，接力开发见 [HANDOFF](docs/HANDOFF.md)。目标形态为 **Windows 桌面 GUI + Linux Web 服务**，本轮以 Windows 为主，HTTP 入口仅用于本地开发。

## 本地运行

需要 Node.js 22、Rust stable；Windows 桌面还需要 MSVC C++ 构建工具和 WebView2。依赖首次安装需要联网，手工阅读与标注不需要模型 API。

```powershell
npm ci
npm run desktop
```

生成独立的调试版 Windows 程序（内嵌前端，不依赖 Vite 服务）：

```powershell
npm run desktop:build
.\target\debug\japread.exe
```

这是本机验收用 EXE，仍依赖系统 WebView2，尚未做签名、安装器和更新发布。

也可在两个终端分别运行 `npm run server` 和 `npm run dev`，访问 http://127.0.0.1:1420。此模式与桌面版共用 Rust 业务核心，使用独立的 `.local/japread.sqlite3`。它仅监听本机，不适合作为公开 Web 服务。

最小体验：导入一篇正文 → 划选同一句内文字 → LLM 解读 → 检查并保存 → 在知识手帐取消／加入学习 → 返回原句。右侧抽屉的「添加注释」可为所选原文或当前解读添加自己的笔记，默认不加入学习；无需 API。抽屉标题固定，内容单独滚动，停止滚动后隐藏滚动条。小说可用单独一行 `---` 分隔章节。可复制 [原创验收短文](examples/reading.txt) 尝试；应用不会自动植入示例数据。

阅读器目录下方可复制解析模板给助手，再粘贴返回的 JSON，检查预览后保存。格式、字符偏移约定及数据位置见 [架构说明](docs/ARCHITECTURE.md)。桌面数据位于 `%APPDATA%/com.japread.desktop/japread.sqlite3`；主题偏好另存于 WebView 本地存储。

青空文库：导入内容 → 搜索作者（姓名／假名）→ 按作品名、类型与文字版本筛选 → 勾选作品 → 导入。首次下载官方压缩目录，后续在本机检索；目录缓存 24 小时。每批最多 10 部，正文串行下载并缓存，重复导入保留已有作品。原书注音和底本／录入校对信息一起保存；无 XHTML 的作品暂需手动导入，图片字保留文字说明。原书注音不会自动加入学习手帐，语法／词汇解析仍是独立步骤。

验证命令：`npm run build`、`cargo test -p japread-core -p japread-sources`、`cargo fmt --all --check`。完整视觉与运行验收记录见 [接力说明](docs/HANDOFF.md)。

## 设置、模型解析与备份

LLM 支持多套配置卡片：无配置时显示添加入口，新增／编辑使用弹窗，点击卡片切换当前模型，后续请求使用当前配置。第一套自动启用，新增其他配置不会切走当前模型；删除当前配置后需手动选择另一套。旧单配置自动迁移为「原有配置」。每套资料及当前选择均存入 Windows 凭据管理器，密钥不回显；编辑留空保留本套密钥，新建不继承其他套密钥。更改接口地址时需重新填写或明确清除密钥。

阅读器右侧未选中时显示本章语境列表，选中后只显示对应解读；点击正文空白处取消选中并收回抽屉。未保存的 LLM 划词结果在点击空白或另一条解读时自动丢弃，迟到的请求结果也不再展示或写入。

左下角「设置」提供阅读与外观、LLM、WebDAV、本机数据四个横向栏目。外观支持浅色／暗夜／跟随系统；颜色独立选择墨绿、柔粉、夜紫、雾蓝、樱花、雨日咖啡，并有实时阅读预览。明暗模式位于色系下方，与右侧预览等宽。旧暖纸偏好自动转为雨日咖啡。支持 16–32 px 正文字号；轻快／标准／舒缓／关闭动画共用于页面、栏目与抽屉，尊重系统减少动态效果。外观偏好只保存在本机，与连接凭据分离。

LLM：填写接口地址、模型名称和 API Key → 保存 → 测试连接与解析 → 打开作品阅读 → 划选同一句内的词句并点击「解读选中文字」。支持 Chat Completions 兼容服务及 OpenAI Responses；接口可填服务根地址、`/v1` 或完整操作地址。严格 JSON Schema 需要服务支持，可按需开启。测试只发送一句固定日文；划词发送当前句作为上下文，只接受准确对应选中范围的解读，预览不自动写入书库，选择保留后才进入手帐。章节／全文批量解析入口暂时隐藏，保留实现并列入 TODO，当前优先完善按需阅读体验。

连接资料整体由 **Windows 凭据管理器** 保存，包括服务地址、用户名、模型、高级参数与密钥／密码。密码保存后不回显，输入留空表示保留，移除连接可清除该服务配置。不写入源代码、SQLite、localStorage 或 WebDAV 备份；localStorage 仅保存外观偏好。桌面版与 Web 开发版使用独立凭据条目，须分别配置。当前非 Windows 环境不提供配置保存，不回退明文。

WebDAV：保存服务地址、用户名、应用密码及子目录后，可测试连接、上传独立版本备份、列出备份并合并。备份含书库、原书注音、笔记、学习选择和进度；不含连接配置及原网页缓存。合并补充缺失记录，已有进度、笔记及冲突作品保留本地内容。**此版本是手动备份／合并，尚非自动双向同步。**

真实服务兼容性需填写自己的配置后验收；本机模拟服务已验证接口和预览保存流程。任务预览目前保存在页面内存中，关闭／重启会丢失未保存结果，暂停在当前批次完成后生效。

## 产品目标

围绕「发现内容 → 选择导入 → 阅读与解析 → 加入学习 → 测验复习 → 回到原文」建立完整流程。新闻、文章与小说章节共用阅读、知识标注和复习能力，让每个知识点都能追溯到学习它的语境。

## 规划能力

### 内容发现与阅读

- 在应用内浏览新闻订阅或作者作品目录，勾选条目后才获取对应正文；刷新列表不自动下载全部内容。
- 探索 RSS / Atom、青空文库目录等来源，保留 URL 与文本导入作为补充。青空文库已接入；RSS / Atom 待实现。
- 区分候选列表、正文导入与结构化解析。导入后即可阅读，解析可稍后进行；摘要或正文提取失败应明确提示，并允许人工补充。
- 保存正文快照、来源链接及导入信息，保留段落、注音和章节结构。小说支持按当前章节、选中章节或全书安排解析。
- 使用缓存、去重和失败退避控制请求；来源内容更新时保留版本关系，不静默覆盖正文与标注。

### 结构化解析与知识关联

词汇、语法和读音按统一格式保存，并与具体原句双向关联：阅读时查看解释，从知识库也能返回作品、章节和原句。全局知识条目与每次出现的语境用法分开记录，避免仅按表面文字合并不同含义。

三种解析入口计划使用同一套数据格式与校验流程：

1. **API 解析**：通过可配置的模型服务进行结构化解析与按需解释。
2. **手工解析**：直接添加、编辑知识点及语境说明。
3. **助手 JSON 导入**：导出原文、句子 ID 和解析规则，将助手返回的 JSON 经格式、原文引用和位置校验后预览导入。

长篇解析计划支持分批任务、进度查看、暂停、取消与失败重试。重新解析需保留人工修订和学习选择。读音、朗读与声调的来源和实现方式仍待选择，不将模型推测当作可靠声调标注。

### 学习选择与可追溯测验

新解析的知识点**默认全部加入学习／测验**，可逐项或批量取消。取消仅改变学习范围，仍保留原文中的解释和关联，不等同于删除知识点。

测验计划从已保存的知识和原句中抽取材料，每题提供答案解释与原文跳转。材料不足或字段缺失时，不生成不满足条件的题目。开启门槛、首批题型、评分方式及复习算法尚未确定。

### WebDAV 同步与独立备份

计划通过 WebDAV 同步正文、标注、知识、学习选择、阅读进度和复习记录，图片与音频可按需纳入。建议同步带独立 ID 与版本的数据记录或交换包，避免多端直接覆盖正在使用的 SQLite 文件。

同步设计需处理并发修改、删除标记、去重与断网重试，并保留可处理的冲突版本。同步不能替代备份，应独立提供导出、备份和恢复。模型服务与 WebDAV 的访问凭据默认不进入学习数据同步。

## 架构思路

建议共享 Web 前端和业务接口，通过平台适配层支持两种运行形态：

```text
共享 Web 前端：内容发现 / 书库 / 阅读器 / 知识库 / 测验 / 设置
                         ↕ 统一业务接口
       Windows 桌面适配                 Linux Web 适配
       Tauri 本地调用                   HTTP 服务接口
                         ↕
       内容管理 / 解析任务 / 学习记录 / 同步与备份服务
                         ↕
       SQLite 与资源存储 / 来源适配器 / 模型服务 / WebDAV
```

前端负责展示与交互；业务服务负责正文与知识管理、解析任务、学习记录和同步规则。平台适配层处理本地调用或 HTTP 访问，存储层管理数据库及图片、音频等资源，来源与模型适配器隔离外部服务差异。接口可先提供模拟实现，支持无 API 的原型验证。

当前小版本采用 Vue 3、TypeScript、Vite、Rust、Tauri 2 和 SQLite。内容模型拟统一为「作品 → 正文／章节 → 段落 → 句子 → 用法标注 ↔ 知识条目」，以稳定 ID、正文版本和资源引用支持定位、交换与后续同步。

Linux Web 服务需要独立规划长期部署、持久化、访问控制、加密传输和凭据保护；临时开发环境不作为生产托管方案。导入内容应经过安全清理，不能获得桌面或服务器权限。Windows 原生运行、系统集成和安装包需在 Windows 上验收，Web 验证不能替代桌面验收。

## 渐进路线

以下为建议推进顺序，不是承诺工期；目前已完成阶段 3 的初步阅读流程，其余能力以 TODO 为准。

| 阶段 | 目标与验收方向 |
| --- | --- |
| 1. 需求与架构 | 明确双端边界、数据模型、业务接口、解析格式及未决项 |
| 2. 交互原型 | 用模拟新闻、文章和多章节小说走通发现、阅读、学习选择与复习，覆盖空状态和失败状态 |
| 3. 最小阅读闭环 | 完成持久化、文本导入、手工／JSON 解析、原文定位与学习选择，验证 Windows 和 Linux 两种适配 |
| 4. 来源接入 | 逐一验证订阅与作品目录，做到只获取选中正文，提供预览和失败补充入口 |
| 5. 自动解析 | 接入模型配置、任务队列、分章处理与人工修订保护 |
| 6. 测验复习 | 验证题目材料门槛、答案追溯和作答记录 |
| 7. 同步与交付 | 验证 WebDAV 冲突处理、备份恢复、Windows 打包及 Linux 部署与访问控制 |
| 后续：EPUB | 导入无 DRM 的本地文字 EPUB，保留阅读顺序、章节、注音和资源，并支持选章解析 |

EPUB 暂不纳入首个阅读闭环；固定版式、扫描书和 OCR 的范围另行评估。后续还需确定具体来源、本地词典与朗读方案、解析合并规则、复习算法、同步协议及界面设计。
